## [llama.cpp b10321 fixes Metal norm kernel bug](https://github.com/ggml-org/llama.cpp/releases/tag/b10321) ⭐️ 7.0/10

llama.cpp release b10321 fixes a Metal kernel bug in ggml_metal_op_norm that caused incorrect NORM/RMS_NORM results when row lengths left a partial simdgroup. The fix rounds up threadgroup sizes to whole simdgroups, and test-backend-ops now passes all 13943 tests on M3 Pro. This fix is significant for users on Apple Silicon who rely on llama.cpp for LLM inference, as it ensures correct normalization results for non-standard hidden sizes. It also demonstrates the project's commitment to correctness and performance, maintaining trust in the widely-used open-source library. The bug occurred because the threadgroup size was clamped to ne00_t, which could be non-multiple of simdgroup size, causing partial sums to be dropped. The fix rounds up to the next multiple of simdgroup size, avoiding unnecessary idle lanes compared to removing the clamp. The issue is reachable with norm shapes like 320-channel norms, though mainstream LLM hidden sizes are unaffected.

github · github-actions[bot] · Aug 7, 19:07

**Background**: Metal is Apple's low-level GPU programming API, and simdgroups are the hardware-level groups of threads that execute in lockstep. In Metal compute kernels, threadgroup memory is used for fast data exchange within a workgroup, similar to CUDA shared memory. llama.cpp is a popular C/C++ library for LLM inference, and its Metal backend is crucial for performance on Apple devices.
