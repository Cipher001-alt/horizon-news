## [Suspicious Discontinuities in Metrics Due to Gaming](https://danluu.com/discontinuities/) ⭐️ 8.0/10

Dan Luu's 2020 article analyzes how artificial thresholds in metrics like marathon times, tax brackets, and latency targets create suspicious discontinuities in data due to human gaming of the system. This phenomenon affects many fields including performance measurement, taxation, and system design, leading to distorted incentives and unintended consequences that can mislead decision-making. The article provides examples such as marathon finish times clustering just under round numbers, tax cliffs creating high marginal rates, and AWS latency targets causing engineers to optimize for P50 and P90 at the expense of tail latency.

hackernews · tosh · Jun 27, 13:32 · [Discussion](https://news.ycombinator.com/item?id=48698151)

**Background**: Metrics and thresholds are commonly used to measure performance or determine outcomes, but when people are aware of these thresholds, they may alter their behavior to meet them, creating artificial discontinuities in the data distribution. This is a form of Goodhart's law, where a measure ceases to be a good indicator once it becomes a target.

**Discussion**: Commenters shared real-world examples from UK tax cliffs, AWS latency fence posts, chess rating distributions on Lichess, and Indian tax surcharges, confirming the universality of the phenomenon and adding practical insights.

## [llama.cpp b9827: CUDA Fast Path for Strided Copies](https://github.com/ggml-org/llama.cpp/releases/tag/b9827) ⭐️ 7.0/10

llama.cpp release b9827 introduces a CUDA fast path in ggml_cuda_cpy that uses cudaMemcpy2DAsync for strided copies, replacing the slower element-wise scalar copy kernel when tensors are non-contiguous but each row is contiguous. This optimization significantly improves GPU memory copy performance for common non-contiguous tensor patterns, such as those in recurrent snapshot updates, benefiting users running large language models with multiple parallel sequences. The fast path is triggered only for same-type, same-shape strided copies where each row is contiguous, and it uses cudaMemcpy2DAsync which is asynchronous with respect to the host. The OpenVINO backend marks this operation as unsupported due to failing new tests.

github · github-actions[bot] · Jun 27, 12:49

**Background**: In GPU computing, tensors are often stored in non-contiguous memory layouts where rows are separated by strides. Previously, llama.cpp used a slow element-wise scalar copy kernel for all non-contiguous copies. cudaMemcpy2DAsync is a CUDA API that efficiently copies 2D pitched blocks, but it requires page-locked host memory and has overhead for each row. This change leverages it for the common case where each row is contiguous, avoiding the scalar kernel's overhead.
