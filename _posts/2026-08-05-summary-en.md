## [Webhooks' Limits for State Sync and a Braid-like Draft Protocol](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

A blog post critically analyzes webhooks' limitations for state synchronization and proposes a draft protocol called SCROLL, which closely resembles the IETF Braid-HTTP Subscriptions draft. The post highlights real-world API inconsistencies, such as QuickBooks returning errors while still creating entities. This matters because webhooks are widely used but often fail at reliable state synchronization, causing data inconsistencies and forcing developers to implement workarounds. The proposal of a standardized protocol like SCROLL or Braid could lead to more robust and interoperable state sync across APIs. The SCROLL protocol uses a GET request with a 'Prefer: stream' header to subscribe to updates, similar to Braid-HTTP. Community comments note that webhooks can be unreliable, as seen with QuickBooks, and that SCROLL may lead to increased polling if consumers lack change notifications.

hackernews · weli · Aug 5, 15:22 · [Discussion](https://news.ycombinator.com/item?id=49184216)

**Background**: Webhooks are HTTP callbacks that notify clients of events, but they are not designed for full state synchronization, leading to issues like missed events and ordering problems. Braid-HTTP is an IETF draft that extends HTTP to support state synchronization by allowing GET to subscribe to updates. SCROLL appears to be a similar concept, though it is presented as a draft protocol in the blog post.
