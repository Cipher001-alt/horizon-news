The article provides historical context and workarounds. This issue affects millions of Polish speakers and highlights broader problems with keyboard input handling and Unicode normalization in web applications. It underscores the need for better internationalization and accessibility in browser design. The article explains that the conflict arises because browsers reserve key combinations like Alt+Shift for shortcuts, which overlap with Polish keyboard layouts for typing diacritics. Workarounds include using Unicode input or changing browser settings.

hackernews · colinprince · Jun 28, 12:44 · [Discussion](https://news.ycombinator.com/item?id=48706814)

**Background**: Polish uses the Latin alphabet with nine diacritic characters (e.g., ś, ć, ż). On standard Polish keyboards, these are typed using AltGr or Alt+Shift combinations. Browsers often intercept these combinations for shortcuts, preventing character input. Unicode normalization can also cause issues, as most Polish diacritics decompose into base letter plus combining mark, except 'ł'.

**Discussion**: Commenters share real-world frustrations, such as Copilot 365 blocking 'Ć' input, and note that the issue persists years later (e.g., Edge on Mac in 2026). Some argue the root cause is browsers lacking a simple way to check key combinations, and developers not building custom handlers. A fun fact is that 'ł' does not decompose in Unicode normalization, causing issues with SQLite's remove_diacritics tokenizer.

**Background**: MUMPS (Massachusetts General Hospital Utility Multi-Programming System) is a high-level programming language with an integrated key-value database, originally developed in the 1960s for healthcare applications. It is still widely used in electronic health records systems, notably Epic Systems. The language is known for its hierarchical database, direct data access, and stringly-typed variables, but also criticized for its terse syntax and historical lack of readability.
