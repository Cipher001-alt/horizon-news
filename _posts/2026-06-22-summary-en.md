## [Deno Desktop Enables Cross-Platform Desktop Apps](https://docs.deno.com/runtime/desktop/) ⭐️ 8.0/10

Deno Desktop has been released, allowing developers to build cross-platform desktop applications using Deno with multiple backends including CEF, Webview, and Raw. Deno Desktop supports CEF (Chromium Embedded Framework), Webview (using the system's native web view), and a Raw backend for custom rendering. The permissions granted at compile time are baked into the binary, and a shared CEF runtime is on the roadmap to reduce binary sizes.

**Background**: Deno is a JavaScript, TypeScript, and WebAssembly runtime built on V8 and Rust, created by Ryan Dahl, the original creator of Node.js. It emphasizes security with a permission system and modern features like TypeScript support out of the box. Desktop application development traditionally requires bundling a browser engine (like Electron) or using native frameworks, often resulting in large binary sizes.

## [Codex logging bug may write TBs to local SSDs](https://github.com/openai/codex/issues/28224) ⭐️ 8.0/10

OpenAI's Codex CLI has a logging bug that writes excessive data to a local SQLite database, potentially causing up to 640 TB of writes per year to a user's SSD. A fix has been committed and is expected in the next release. This bug can drastically shorten SSD lifespan, as a typical 1 TB consumer SSD is rated for about 600 TBW (terabytes written). Users may experience drive failure in under a year if the bug is left unchecked, affecting productivity and hardware costs. The bug is in the logging sink of Codex CLI, which writes to ~/.codex/logs_2.sqlite. ## [Linux Secure Boot Certificate Expiration Looms in 2025](https://lwn.net/Articles/1029767/) ⭐️ 8.0/10

The Linux Secure Boot certificates, used to sign bootloaders like shim, are set to expire in 2025, potentially causing many Linux systems and virtual machines to fail to boot after the expiration date. This expiration could affect a large number of Linux machines worldwide, disrupting operations for users and administrators who rely on Secure Boot for system integrity, especially if they are unaware of the need to update certificates. The expiration involves Microsoft's UEFI CA certificate used to sign Linux shims; however, some sources note that Secure Boot firmware does not validate certificate expiration dates at boot time, so the actual risk may be lower than feared.

hackernews · weaksauce · Jun 22, 18:24 · [Discussion](https://news.ycombinator.com/item?id=48633941)

**Background**: Secure Boot is a UEFI firmware feature that ensures only signed, trusted bootloaders and operating systems can run during system startup. Linux distributions use a small bootloader called 'shim' that is signed by Microsoft's certificate to chain-load the GRUB bootloader and kernel. When the signing certificate expires, newly built shims may not be trusted by firmware that checks expiration, though existing installations may continue to work.
